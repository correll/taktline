# Taktline

Browser-based digital Kanban / Manufacturing Execution System (MES) that models production flow as a directed graph. Lot-cards travel with physical lots through locations, operators log work at stations via a mobile dashboard, and the system collects real-time OEE and takt-time statistics.

---

## Architecture

```
taktline/
├── backend/        FastAPI + PostgreSQL (async via SQLAlchemy 2.0 + asyncpg)
│   └── app/
│       ├── main.py             App entry-point, CORS+CSRF, auth'd WebSocket, plugin lifespan
│       ├── core/               Config, argon2 security, mailer, CSRF middleware, rate limiter
│       ├── db/                 Async engine, session dependency, ORM tables (SQLAlchemy)
│       ├── deps/               Auth/tenancy dependencies (current user, active company, admin)
│       ├── models/             Pydantic v2 API schemas with domain validators
│       ├── routers/            REST endpoints (one file per domain object)
│       └── plugins/            Machine adapter plugin system (mock + base class)
│   └── alembic/            Database migrations (autogenerated from ORM metadata)
└── frontend/       React 18 + TypeScript + Vite
    └── src/
        ├── api/                Axios wrappers for each backend resource
        ├── components/         Reusable UI — lot cards, map nodes, modals
        ├── domain/             Domain logic: graph.ts (DAG utils), invariants.ts (assertions)
        ├── store/              Zustand stores with immer + devtools middleware
        ├── theme/              Design tokens (colors, spacing, typography)
        └── views/              Full-page views
            ├── lots/           Kanban view — columns per location, topological order
            ├── dashboard/      Location selector (portrait / phone / iPad mode)
            ├── operator/       Single-station timer view with session recording
            ├── statistics/     OEE and takt-time per station
            └── settings/       Map config, processes/routes, stations, templates
└── connectors/     ERP integration services (anti-corruption layer)
    └── odoo/       Odoo ↔ Taktline connector: MOs → /orders (pull); completion → mark MO done
```

ERP connectors are standalone services that map an external system's orders onto
Taktline `POST /orders` (which releases a pull) and drain the completion
`/orders/outbox` back to the ERP. See [connectors/odoo/README.md](connectors/odoo/README.md).

### Domain model

| Concept | Description |
|---|---|
| **Location (Station)** | A physical place where manufacturing happens. Nodes in the process graph. |
| **Route** | A directed edge between two locations. `quantity` = units of upstream product consumed per assembly cycle. |
| **Process** | A named collection of routes forming a DAG. Multiple processes can coexist. |
| **Lot template** | Per-product card template. `startStationId` pins it to a source node (queue origin). |
| **Lot card (Card)** | Travels with a lot of physical products. Carries `totalQuantity` units distributed across `bins` (one bin per current location). Bin totals ≤ `totalQuantity` is a hard invariant. |
| **Session** | An operator's work timer at a station. Records `durationSec` and `quantity` processed; feeds OEE and takt-time aggregation. |
| **Queue / source node** | A location with no incoming routes — the origin point where new lot cards are injected. |
| **Merge node** | A location with 2+ incoming routes — where precursor lots are consumed and a new assembly lot card is created. |
| **User** | An authenticated account (email + argon2 password hash, email-verified). |
| **Company** | A tenant. All process data (stations, routes, cards, sessions, settings) belongs to exactly one company. |
| **Membership** | A user's role (`admin` or `member`) in a company. One user can belong to many companies. |
| **Invitation** | An admin's email invite to join a company at a given role; single-use, expiring, hashed at rest. |

### Key design decisions

- **Process graph is a DAG** — cycle detection runs at every route create/update (backend DFS + frontend pre-flight check). The topological sort that drives Kanban column order relies on this.
- **Quantity conservation** — `sum(card.bins) ≤ card.totalQuantity` is enforced by a Pydantic `model_validator` at creation; the `/move` endpoint preserves the invariant structurally.
- **Database-enforced integrity** — foreign keys (`ON DELETE CASCADE`/`SET NULL`), `CHECK` constraints (`quantity ≥ 1`, no self-loop routes, `totalQuantity ≥ 1`, status/unit enums), and a unique `(processId, load, unload)` route edge live in Postgres. Each request runs in a single transaction (via the `get_session` dependency), so multi-write endpoints like `/merge` and `/cards/{id}/move` are atomic.
- **Authentication & multi-tenancy** — httpOnly cookie sessions (opaque token, hashed at rest), argon2id passwords, required email verification, CSRF double-submit tokens, and rate-limited auth endpoints. Every domain row carries a `companyId`; the `get_active_company` dependency scopes each request to the caller's active company (`X-Company-Id` header) and `require_admin` gates configuration and member-management endpoints. Members get read-only Lots + operator timers; admins configure the process and manage the team. Server-side authorization is the source of truth — the frontend gating is UX only.
- **Real-time sync** — the backend pushes all state changes over a single WebSocket (`/ws/events`); the frontend Zustand stores apply patches on receipt.
- **Plugin system** — each station can have a `adapterType` that maps to a plugin class. The mock adapter simulates machine state; real adapters (OPC-UA, Modbus, etc.) can be added without changing core logic.

### API surface

All endpoints are prefixed by resource:

All domain endpoints require an authenticated session and an `X-Company-Id` header identifying the active company; unsafe methods also require the `X-CSRF-Token` header.

| Prefix | Resource |
|---|---|
| `/auth` | Signup, email verification, login/logout, `/me`, password reset |
| `/companies` | Create / list-mine / get companies |
| `/companies/{id}/members` | List members, change role, remove (admin) |
| `/companies/{id}/invitations` + `/invitations/{token}` | Invite / list / revoke; public preview + accept |
| `/stations` | Location CRUD + position updates |
| `/routes` | Route CRUD (with cycle/self-loop validation) |
| `/processes` | Process and lot-template CRUD |
| `/lot_templates` | Lot card template CRUD |
| `/cards` | Lot card CRUD + `/cards/{id}/move` |
| `/orders` | Production orders (release/pull, completion) + `/orders/outbox` for ERP delivery |
| `/sessions` | Work session start/end + per-station stats |
| `/map_settings` | Floor plan URL, pixels-per-unit, unit calibration |
| `/global_settings` | App-wide settings |
| `/stats` | OEE and takt-time aggregation |
| `/uploads` | Static file serving for uploaded floor plan images |
| `/ws/events` | WebSocket broadcast channel |

Interactive docs: `http://localhost:8000/docs`

## Setup

### 1. Backend

```bash
cd backend

# Create and activate virtual environment
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

# Install dependencies
pip install -r requirements.txt

# Create the database (once) and apply migrations
createdb taktline
alembic upgrade head

# Start the API server (reload on file changes)
uvicorn app.main:app --reload --port 8000
```

PostgreSQL is expected at `postgresql+asyncpg://localhost:5432/taktline` by default (local trust auth uses your OS user, no password). Set `DATABASE_URL` as an environment variable to override — e.g. `postgresql+asyncpg://user:pass@host:5432/taktline`. `alembic upgrade head` creates the schema; re-run it after pulling new migrations.

**First run / auth.** The app requires an account. Copy `backend/.env.example` to `backend/.env`. In development, run with `TAKTLINE_DEV=1` so verification/invite links are returned in API responses (no SMTP needed) and the dev bootstrap used by `seed_demo.py` is enabled. Then either open the app and use **Create account → verify → create a company**, or run `TAKTLINE_DEV=1 python seed_demo.py` to create a demo admin (`demo-admin@taktline.dev` / `demo-password-123`) with the full E-Bike process. Configure `SMTP_*` in `.env` to send real email; set `COOKIE_SECURE=1` and a strong `SECRET_KEY` in production.

### 2. Frontend

```bash
cd frontend

# Install dependencies
npm install

# Start the dev server
npm run dev
```

The app is served at `http://localhost:3000` and proxies API calls to `http://localhost:8000`.

### 3. Production build

```bash
cd frontend
npm run build          # outputs to frontend/dist/
```

Serve `frontend/dist/` as static files, or set `FRONTEND_DIST` so the FastAPI
service serves the SPA itself (same-origin). **[IOS.md](IOS.md)** covers the iPhone/iPad story — an installable
home-screen app today, and a Capacitor App Store build in `frontend/ios/`.
**[DEPLOY.md](DEPLOY.md)** is a
step-by-step deployment to Render (app + Postgres) with Resend for email, and
the `Dockerfile` it uses runs anywhere else that takes a container.

### 4. Tests

```bash
cd backend
createdb taktline_test                      # once
pip install -r requirements-dev.txt
python -m pytest                            # auth, tenancy, RBAC, upload & injection safety
```

The suite runs against a dedicated `taktline_test` database and covers the
security invariants (email verification, CSRF, tenant isolation, the role matrix,
last-admin guard, upload validation, security headers, WebSocket origin,
injection round-trips, and rate limiting).

## Development notes

- **Hooks before early returns** — React function components must call all hooks unconditionally before any `return null` guard. This is enforced by the `react-hooks/rules-of-hooks` ESLint rule and is a documented invariant in `src/domain/invariants.ts`.
- **Domain assertions** — `src/domain/invariants.ts` exports typed `assert*` helpers that throw in development and log in production. Call them at store boundaries and in critical computation paths.
- **Graph utilities** — `src/domain/graph.ts` provides `hasCycle`, `wouldCreateCycle`, `sourceNodes`, `mergeNodes`, and `topoSort`. Use these instead of duplicating graph traversal logic.
- **Passive wheel events** — the map canvas attaches its wheel handler with `{ passive: false }` via an imperative `addEventListener` in a `useEffect`. Do not convert it to a React `onWheel` prop; React 17+ registers those as passive, which silently drops `preventDefault` and can cause scroll-induced layout shifts that break the hooks count.
